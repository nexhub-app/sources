# 非程序员模式：让用户只提供「网址 + 想看什么」

目标：用户不懂选择器、JSON、脚本，也能得到一个能用的源。
做法：**用户只回答大白话问题，技术判断全部由 AI 做**；每轮只推进一小步，每步都给可验证的结果。

## 1. 开场：只问三件事

用下面这套话术（可改写，不许问技术细节）：

```
我可以帮你做一个源，全程你只需要回三个问题：
1）站点的首页网址是什么？
2）你想在这个站看什么：动漫 / 漫画 / 小说？
3）平时在浏览器里打开它，需要登录吗？
```

不要问：解析方式、选择器、JSONPath、要不要写脚本、`useWebview` 开不开 —— 这些由 AI 探测后自己定。

## 2. 第二条消息：再要两个链接

```
再给我两个链接，我就能开始：
· 一个"搜索结果页"的链接（在这个站搜任意关键词后的地址）
· 一个"具体作品详情页"的链接
```

有这两个页面，就能确定列表结构和详情结构；没有的话退化到首页 + 猜路径，成功率明显下降。

如果用户只能给一个链接：先做首页列表 + 详情，搜索留空不写路由（应用会隐藏搜索入口，不会报错）。

## 3. 执行顺序（内部步骤，不要讲给用户）

1. `python scripts/probe_site.py <首页>` → 判定类型（接口 / 直连 / 需渲染 / 强反爬）。
2. 抓一个真实页面样本（`curl` 或 `--save`）→ 挑容器与字段选择器。
3. 复制对应模板 → 填 `id` / `name` / `site.baseUrl` / 路由 / 选择器。
4. `python scripts/validate_source.py 源.json` → 必须无 ERROR。
5. 交付 + 让用户在真机验证。
6. 有反馈 → 按 `troubleshoot.md` 定位，只改那一处，`version` +1 再给。

## 4. 交付时怎么说（模板）

```
源已经做好了，文件名：xxx.json
导入：源管理 → 右上角 + → 导入文件 → 选这个 json
导入后先测这三步：
① 首页能看到卡片（封面 + 标题）
② 搜一个关键词能出结果
③ 点开一部 → 目录能展开（影视是选集，漫画是章节）
哪一步不对，把截图发我，我改。
```

几个用词替换（说人话）：

| 不要说 | 要说 |
|---|---|
| 选择器 / selector | 抓取规则 |
| JSONPath / CSS | （不提，直接说"我按页面结构配好了"） |
| 端点 / route | 页面（首页 / 搜索页 / 详情页 / 目录页 / 播放页） |
| parser / overrides | 解析方式（"这个站要开着浏览器才能看，我给它配了浏览器模式"） |
| version +1 | 更新了版本号，重新导入会覆盖旧的 |

## 5. 分阶段交付，别一次承诺全部

| 阶段 | 内容 | 用户可见结果 |
|---|---|---|
| 第 1 步 | `search` + `detail`（或 `latest` + `detail`） | 能搜到、能打开详情 |
| 第 2 步 | 目录 / 章节 | 能看到选集或章节 |
| 第 3 步 | 图片 / 播放 / 正文 | 能看能播 |
| 第 4 步 | 分类、首页板块、筛选 | 更好用 |

每完成一步就交付一次，用户能立刻看到进展，也便于定位问题。

## 6. 让用户"帮你看页面"的正确姿势

需要判断结构时，不要让用户读 HTML，而是：

```
在浏览器打开这个页面，按 F12 → 点左上角的小箭头 → 点一下任意一个作品封面，
然后把你看到的右边那一行（以 <div 或 <li 开头）截给我。
```

或者更省事：

```
右键 → 查看网页源代码 → 全选复制 → 粘贴到一个 txt 发我。
```

（AI 拿到 HTML 就能自己定位，比让用户描述可靠。）

## 7. 验收清单（发给用户，逐条打勾）

- [ ] 首页/发现页有卡片，封面不是灰块
- [ ] 搜索关键词能出结果，翻页不重复
- [ ] 详情页标题、简介正确，不是别的作品
- [ ] 目录/选集条数与网页一致
- [ ] 漫画图片能加载、顺序正确；或视频能播放
- [ ] 二次进入（冷启动）仍然正常

## 8. 失败反馈怎么收

让用户按这个格式回，一次就能定位：

```
哪一步：首页 / 搜索 / 详情 / 目录 / 播放 / 图片
现象：空白 / 报错文字 / 图裂 / 一直转圈
截图：（附上）
最近改动：（如果是改完才坏的）
```

对应到 `troubleshoot.md` 的章节，只改相关字段。

## 9. 边界：什么时候要跟用户说"这个站做不了"

- 站点必须登录且注册要手机号/邀请码 → 说明只能做「登录后可用」，且不建议内置分发。
- 内容靠 DRM（Widevine 等） → 不能做。
- 站点全站 Cloudflare 且每次都要点验证，且资源本身也有签名 → 可以做但体验差，提前说清楚。
- 用户要的是「破解付费墙」→ 明确拒绝，只做页面本身公开可见的内容。
